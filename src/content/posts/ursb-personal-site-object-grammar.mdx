# ursb.me 的个人主页对象语法

[ursb.me](https://ursb.me) 是一个很强的个人主页参考，但它的价值容易被误读。

表层看，它内容很多：项目、文章、笔记、频道、照片、运动、音乐、设备、软件栈、阅读、电影、咨询和留言。浅层模仿会得出一个错误结论：高级个人主页等于把更多模块放到首页。

真正值得学的是另一件事：它把很多松散的个人材料都变成了可探索对象。

## 对象语法，不是信息密度

这个站点的高明处不是“满”，而是每个区域都在回答一个对象问题：

- 项目不是一句自夸，而是有产品链接、App Store 链接和标签。
- 文章和笔记不是装饰目录，而是持续更新的内容流。
- 照片、运动、音乐、阅读和电影不是生活碎片，而是带来源和时间感的状态对象。
- 技能、设备、软件栈不是简历填空，而是解释这个人如何工作。
- 咨询和留言不是随手放的 CTA，而是把读者行动接到一个明确入口。

所以它不是传统 portfolio，也不是普通 blog。它更像一个个人操作系统的公开外壳：你能看到一个人的项目、注意力、工具、身体状态、阅读状态和社交入口如何共同运转。

## 我们应该借什么

Ray Studio 应该借三件事。

第一，借对象边界。我们的 `/blog`、`/projects`、`/knowledge`、`/uses`、`/photos`、`/music`、`/lab` 不应该只是栏目名，而应该各自回答“这个对象是什么、来源是什么、下一步能去哪里”。

第二，借状态诚实。好的个人主页不必伪装成企业级控制台，但它应该展示真实状态：最近在写什么、正在维护什么、哪些内容是实验、哪些内容已经发布。

第三，借跨域连接。项目可以连接文章，文章可以连接 Knowledge，Knowledge 可以连接源码、部署和组件。一个高级个人主页的魅力，来自这些对象之间的路径，而不是来自任何单一卡片的视觉效果。

这也解释了为什么本站前面坚持做 `Related reading`、Knowledge backlinks、Evidence Pack、Command Center 和 release evidence。它们不是功能炫技，而是让对象之间有路。

## 不要复制它的体量

最危险的做法，是看到 `ursb.me` 的丰富度后立刻扩大首页。

这对 Ray Studio 现在是错的。我们的站点还处在内容可信度和外部证据积累阶段，贸然增加运动、阅读、电影、咨询、留言、实时数据、更多小组件，只会制造“看起来像 OS”的幻觉。

更正确的策略是：先把少量对象做硬。

- 文章要有观点、上下文和读后用途。
- 项目要有外部对象、证据包和取舍。
- Knowledge 要能被引用，并且能反向指回真实页面。
- Lab 要证明组件可复用，而不是像内部玩具箱。
- Uses 和 About 要解释工作方式，不要堆工具名。

`ursb.me` 给我们的不是一张组件清单，而是一条产品原则：个人主页越个人，越需要对象化；对象越多，越需要克制的路径设计。

下一步不要问“还能加什么模块”。应该问：现在已有对象里，哪一个还没有足够清楚的来源、状态、去处和证据。
