# Phase 45：真实媒体替换计划

日期：2026-07-10

## 现状与判断

`/photos` 与 `/music` 不是空路由：它们可从首页与 Command Center 到达，且明确披露了 Generated、Unsplash、Reference、Mock 等来源边界。但它们仍不是个人纪实相册或真实播放系统。继续给 reference 素材补文案，不会把它变成真实记忆层。

本阶段不伪造“已拥有真实照片/音频”的状态，也不接入未经确认的流媒体或版权素材。目标是让替换发生时不破坏现有路由、组件、索引、信任说明和部署链。

## 替换原则

1. 真实优先：个人照片和本人拥有或明确授权的音频，优先于更漂亮的参考图。
2. 来源可见：每个素材保持 `origin`、`sourceLabel`、`sourceHref`（如适用）、记忆强度与保留理由。
3. 渐进替换：先替换首页精选对象，再建立专辑或完整播放能力；不要一次重写整层。
4. 不伪造播放：没有实际音频文件时，控制器只能是 mock state，不能暗示正在播放真实音频。
5. 内容优先：媒体只能加强个人气质，不替代文章、作品与证据。

## 资产登记格式

每个候选资产进入仓库前应记录以下字段：

| 字段 | 照片 | 音频 |
|---|---|---|
| 所有权/授权 | 本人拍摄或明确授权来源 | 本人创作、购买许可或可公开嵌入的来源 |
| 来源标签 | `Personal` / `Reference` 等 | `Local` / `External` / `Mock` |
| 公开范围 | 可公开、仅私有、需要裁切/脱敏 | 可公开播放、仅元数据展示、不得嵌入 |
| 叙事价值 | 为什么它属于此页 | 出现在哪个工作状态或文章路径 |
| 技术资料 | 原始文件、导出尺寸、alt 文本 | 文件格式、时长、封面、许可与播放策略 |

## 分三步替换

### A. 首个真实照片切片

- 交付 3-6 张本人可公开的照片：一张工作台、一张空间或行走观察、一张不直接暴露隐私的生活质感。
- 优先替换首页 `Morning studio desk` 与 `/photos` 的 featured 卡。
- 保留原始文件在不公开的资产目录；只提交经过导出、裁切、命名和 alt 审核的发布文件。
- 将 `origin` 改为 `Personal`、`memoryStrength` 改为 `Personal`，并重写 `whyPreserved` 为实际事件或观察，而不是氛围占位。
- 验收：桌面/移动截图、灯箱、Command Center 索引和来源披露均通过。

### B. 真实音乐的最小闭环

- 先选择一个具有明确许可的本地音频文件，或只展示真实曲目元数据与外部合法链接。
- `sourceState: Local` 只在浏览器确实可以加载允许公开的文件时使用；否则使用 `External` 并链接到合法播放页。
- 增加真实播放前，先定义停止、加载失败、静音、键盘操作和移动端降级；不要让假进度条先于音频存在。
- 验收：播放控制的可访问名称、错误状态、reduced motion、移动端控制尺寸和许可链接。

### C. 叙事层，而非素材堆

- 当真实照片达到 12-18 张且有可解释的时间/地点/主题关系时，再增加 album 结构。
- 当真实音频达到 3-5 个可公开对象时，再决定是否使用小型播放列表。
- 在这之前，维持现有 Media card 的双入口，不把导航主栏扩成媒体产品。

## 替换时的回归清单

- 运行 `npm run validate:content` 与 `npm run report:command-index`。
- 检查 `/photos`、`/music`、首页 Media card 和 `/command-index.json` 的对象数是否一致。
- 复核图片压缩、尺寸、alt 文本与灯箱布局，避免 LCP 和移动端裁切退化。
- 复核音频许可、播放失败反馈、键盘导航与 reduced motion。
- 部署后运行 RayNode health、full routes、smoke 和媒体定向 Playwright 测试。

## 阻塞条件

在以下条件不满足前，不把媒体层称为真实个人档案：没有可公开的本人资产、没有音频许可、没有来源记录、或没有完成移动端与生产环境验证。
